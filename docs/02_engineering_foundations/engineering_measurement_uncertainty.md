# 工程数学、度量与不确定性：读懂规格表之前的共同基础

半导体与 AI 系统跨越多个数量级，单位、边界或统计口径的小错误，会在集群和财务模型中被放大。本章不追求抽象证明，而是训练把“更快、更省、更稳定”还原为可测量、可重复和可证伪的命题。

~~~mermaid
flowchart LR
  Q[问题] --> B[边界]
  B --> U[单位与变量]
  U --> M[测量]
  M --> D[分布]
  D --> C[结论]
  C --> F[证伪条件]
~~~

## 量与单位

**基础直觉：**量是可比较的属性，单位建立共同尺度；数字脱离单位没有工程意义。

**必须区分：**bit/byte、周期/秒、功率/能量、摄氏温度/温差。

**工程使用：**先写对象、边界、单位、方向、配置、状态与时间窗口，再说明数据来自 instrument、counter、日志还是估算。每一步计算保留量纲，并用上限、下限或另一条独立路径做 sanity check。

**常见误区：**不要把单点、平均值或 headline 当完整分布，也不要让结果精度超过输入证据。局部指标改善后必须重测端到端 waterfall，因为旧瓶颈消失会改变比例、排队和尾部。

**交流追问：**原始单位、前缀、方向和换算链是什么？看到什么结果会推翻当前判断？

## 综合练习

选择任意一张芯片或系统规格表，隐藏产品名称，只保留数字。为每个数字补齐对象、单位、方向、精度、条件、测量点、样本分布和证据等级；再建立乐观上限、保守下限和一个可复现实验。无法完成这些字段的数字，只能进入待验证清单，不能直接进入采购或估值模型。
