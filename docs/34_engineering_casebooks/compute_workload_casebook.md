# 计算、架构与工作负载工程案例手册

> 版本日期：2026-08-28。本手册把 glossary 概念转成计算、测量、故障注入与决策工作底稿。每次只选一个真实 workload 和 system boundary，先写基线与目标，再完成计算、测量和恢复演练。产品状态必须附日期；规格、厂商主张和分析分别标注 [Primary Source]、[Vendor Claim] 与 [Inference]。

本卷覆盖 49 个术语。核心观察面：硬件计数器、内核轨迹、占用率、停顿分类与关键路径；决策面：质量固定后的有效吞吐、延迟分位数、能耗和移植成本。

### 1. 算术强度（Arithmetic Intensity）

**基础直觉与边界。** 每搬运一个 byte 数据完成多少次有效运算。先把它当成可观察机制：对象、输入输出、状态位置、推进事件和终止边界都要写清。前置概念是operations、memory_traffic。若这些前提未统一，同一词在芯片、系统软件、运维和商业团队口中可能代表不同对象。

**系统位置。** “算术强度”位于指令、算子、内核、执行阵列与端到端工作负载之间。图中标出上游生产者、下游消费者、共享资源、控制面和故障域，再沿正常、饱和、错误、恢复四条路径追踪状态。先算理论上限，再用利用率与暴露时间逐层折减；模型应指出下一项最值得测的变量。 还要说明优化后压力移到哪一级缓存、队列、链路、供电、散热、软件或制造步骤；只写局部收益没有完整因果链。

**计算骨架。** 设观察窗口内有效工作量为 (G)，与“算术强度”相关事件数为 (N)，每次资源需求为 (r)，协议、等待或恢复附加比例为 (o)，并行份数为 (p)。总需求 (D=N\times r\times(1+o))，最低服务时间 (T_{min}=D/(C\times p))。实测 (T_{obs}) 与最低时间之差应拆成排队、依赖、空闲、重试、降频和未覆盖路径。有效效率写成 (E=G/(T_{obs}\times C\times p))，并按 workload shape 分桶，防止平均值掩盖长尾。

**测量计划。** 直接证据采集硬件计数器、内核轨迹、占用率、停顿分类与关键路径；端到端看质量固定后的有效吞吐、延迟分位数、能耗和移植成本。每个数记录对象、单位、周期、分位数、温度、版本、拓扑、功率模式和误差。三组对照分别固定软件改硬件、固定硬件改工作负载、注入压力再恢复。局部 counter 与端到端结果必须同时间轴对齐，否则只能证明相关，不能排除共同原因。

**故障演练。** 依次改变批量、序列、形状、精度、并发、依赖和稀疏度，预期暴露执行单元空闲、流水线气泡、依赖阻塞、寄存器压力和尾部请求拖慢。演练前定义基线、阈值、检测、隔离、降级与恢复完成条件；演练后排查静默错误、重试放大、错误归因和监控盲区。分别记录首个异常、首个用户影响和恢复稳定时刻，用以区分检测慢、隔离慢和恢复慢。恢复后还要复测性能与正确性，避免“服务已启动”却仍处于降级状态。

**为什么不能只做更大或更快。** 扩大资源会增加面积、功耗、布线、验证或库存；局部容量在串行依赖或供给不足时会闲置；更大共享域会扩大争用和故障爆炸半径。至少比较增加数量、增强单体、改变分片调度、减少需求与接受降级五条路径。所有方案固定质量与服务等级，避免低精度、少工作或宽松延迟伪装成架构优势。

**工程语言与证伪。** 听到“算术强度已解决”“几乎无开销”，改写为：截至何日，在何硬件步进、固件、驱动、模型、形状、并发、温度和故障条件下，哪个分位指标相对哪条基线改善，证据来自规格、测试、客户部署还是推断。证伪条件包含边界 workload、故障注入和跨版本复现；失败应降级结论，不能临时换基准。

**工程到战略。** 把局部变化依次传导到合格产出、部署时间、有效吞吐、可用率、单位工作成本、切换成本与议价权。最终观察质量固定后的有效吞吐、延迟分位数、能耗和移植成本。若收益依赖未发布软件、未认证供应或未完成设施，状态只能写 roadmap、sampling 或 qualification，不能计入当期收入。再问竞争者能否用软件、更多旧设备、不同拓扑或价格抵消优势。

**现场工作单。**

1. 写出“算术强度”的对象、边界、目标函数和日期。
2. 给出理论、保证、典型与尾部值，并解释差额。
3. 指定直接 counter、用户结果、质量门禁和恢复指标。
4. 画正常、饱和、错误、恢复路径与责任界面。
5. 找到推翻主张的测试、阈值和原始日志，否则标为 [Inference]。
6. 把结论写成采购门槛或尽调里程碑，不使用“领先”“成熟”等空泛词。
